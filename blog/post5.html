Post 5: Web Design Research

February 26, 2026

For this final blog post, I watched the video about why CSS can feel “weird,” and I also read a Smashing Magazine article about eco-friendly interfaces. Together, they helped me think about web design as both a technical system (how CSS behaves) and a responsibility (how design choices affect performance, usability, and even energy use).

Video Reflection: Why CSS is so weird

The video I watched was “Why CSS is so weird” My biggest takeaway is that CSS wasn’t designed like a strict programming language. It was built to style documents that can change, adapt to different screens, and work across browsers. That flexibility is why CSS includes rules like the cascade, inheritance, and default browser styles — and why a small change sometimes creates a surprising result somewhere else.

In this course, I often fixed CSS problems by trying different things until it looked right. After watching the video, I understand debugging more logically: I should check which rule is winning (specificity and source order), whether a style is inherited, and how layout rules like normal flow, the box model, or Flexbox are affecting the final result. This makes CSS feel less frustrating and more predictable.

Article Review

The article I chose is from Smashing Magazine: “A Designer’s Guide To Eco-Friendly Interfaces”. The main idea is that “Sustainable UX” is not just a trend — it is a design mindset where performance and efficiency become part of the responsibility of a designer. The author explains that big visual assets, autoplay media, and heavy animations aren’t only annoying or slow; they also increase the amount of energy required to load and render a page.

Key Points I Learned

One point that stood out to me is that eco-friendly design often overlaps with good UX. For example, optimizing images and videos makes pages load faster, which improves the user’s experience. The article also discusses design decisions like using dark mode thoughtfully, reducing unnecessary motion, and setting a “data budget” for a page so the team makes more intentional choices instead of adding features endlessly.

I also liked the idea that constraints can produce better design. If you limit file size, reduce extra fonts, and avoid “loud” animations, the result can look cleaner and feel more focused. This connects to what we learned about hierarchy, spacing, and clarity in interface design.

Connection to This Course

This article connects directly to our blog project requirements. We were asked to optimize images for the web and keep them under 200K. Before, I treated that as just a technical rule. After reading this article, I see it as part of responsible design: smaller images reduce load time, reduce data usage, and improve accessibility for users on slower connections.

The article also reinforced the importance of writing clean HTML and using CSS efficiently. When my structure is clear (headings, sections, navigation), I can style the page with fewer “patches” and less complicated code. If I rely too much on extra assets or overly complex effects, the page becomes harder to maintain and can create a worse experience.

Reflection

Overall, the video helped me understand CSS as a rule-based system, and the Smashing Magazine article helped me think about the real-world impact of design decisions. I used to focus mostly on “does it look good?” Now I also think about “does it load fast, stay readable, and work well for users?” and even “is it efficient and intentional?” Going forward, I want to design with fewer unnecessary elements, optimize my assets, and write CSS that is simpler, clearer, and easier to debug.
