Post 2: Artical HTML

February 3, 2026

Your Article HTML

In the article that I recently wrote and styled, I realized that I could have done a better job using semantic HTML. At first, I focused mostly on how the page looked visually. As long as the layout felt clean and organized, I thought my work was finished. After reading the article on semantic HTML, I started to understand that structure is just as important as visual design.

Using semantic elements such as < article >, < section >, and < nav > helps define the purpose of each part of a page. Instead of using < div > for everything, these elements make the code easier to read and understand. They also help browsers and assistive technologies better interpret the content. Looking back at my article, I realized that using semantic HTML more intentionally would have made the structure clearer and more meaningful.

Why Semantic HTML Matters

Semantic HTML is not only about cleaner code. It helps organize content in a logical way and creates a clearer hierarchy for readers. Headings divide content into sections, and navigation elements allow users to move through the page more easily. This connects to my previous post, where I focused on visual hierarchy. Semantic HTML supports that visual design by giving the content a solid structure first.

What I Learned About the Process

I also realized that coding requires much more patience and attention to detail than I expected. I have had many experiences where my code did not work because of a small spelling mistake or an incorrect symbol. Each time this happened, I felt very frustrated because I could not immediately figure out what went wrong. In those moments, I often lost patience and rushed to ask for help.

Through this process, I started to understand that coding is not just about making things work quickly. It is about slowing down, checking details carefully, and staying calm when something breaks. Rushing usually makes the problem harder to solve.

Moving Forward

Going forward, I want to approach coding with more patience and focus. I will spend more time reviewing small details and be more confident in troubleshooting on my own before asking for help. This experience helped me realize that both design and coding require persistence, and learning how to stay patient is an important part of becoming a better designer.
